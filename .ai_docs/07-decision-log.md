| ADR-019 | **Error codes are stable API** (E####/W####, registry in `lumen-core/diagnostics.md`). | Agents pattern-match on codes; never reuse or renumber. |
| ADR-020 | **License: MIT OR Apache-2.0; `cargo-deny` enforces compatible deps.** | |
| ADR-021 | **Reactive identity is `impl Hash + Debug`, not `&str`** (refines ADR-007's "call-site path + explicit keys"). `cx.signal`/`cx.scope`/`Runtime::signal`/`memo`/`effect` accept any `Hash + Debug` key; identity = a seed-free **128-bit** `IdHash` folded from the enclosing scope's hash + the local key's hash (egui `Id` model, widened). A readable name is materialized **once on the cold intern path** to keep snapshot restore (ADR-011) and agent dep-name observability (ADR-009); `key_name` strips the quotes `Debug` puts around a string key so pre-existing snapshot keys still match. `&str` is `Hash + Debug` ⇒ a strict superset (existing call sites unchanged); enum/int/tuple keys address allocation-free. Hashing is pinned by our own `IdHasher` (not `DefaultHasher` — SipHash is unstable across Rust releases) and is endian-independent, or snapshots/goldens break. **Hashes cannot be prefix-matched**, so scope-local eviction (F5 list GC) is by recorded slot ownership + a scope tree (`evict_scope`), not `evict_prefix`. Measured: re-addressing 1 000 per-row signals went 51.0 µs / 1 000 allocations → 18.2 µs / **0**. | Kills the per-frame `format!` key + per-item intern-string allocation that made per-list-item state expensive; the identity primitive keyed lists (`For`, F5) consume. Pre-1.0, no external projects → the §2.3 API-freeze escalation is moot (per the 2026-07-03 F3 precedent). Plan: `docs/plan-hash-identity.md`. |

## 3. Agent amendments & locked versions
*(Append-only. Format: date — task — decision — rationale.)*

- 2026-08-12 — SR1 — **A direct present reports *why* it declined (`Present::{Done,Skipped,Unavailable}`), and only the permanent answer tears the surface down.** Reported from Mercurium as a `Surface::configure: Invalid surface` panic when resizing after login; reproduced here with no Mercurium involved — `just run datagrid` plus 129 rapid `wmctrl` resizes, and the identical panic. **The chain:** `present_to_surface` returned `bool` and had three ways to say `false` — no surface attached, the swapchain went `Outdated`/`Lost` mid-resize and the one retry also missed, and no display list yet. The shell read every `false` as "the window outgrew the device's texture limit" (its comment asserted that was the only cause, which stopped being true when the Outdated-retry landed), so **one skipped frame during a drag** permanently set `direct = false` and constructed a CPU `Presenter` — which creates a *second* wgpu surface on the same window and calls `Surface::configure` while the drag is still running. wgpu-core 22 maps a configure-time out-of-date to `ConfigureSurfaceError::InvalidSurface` and routes it through `handle_error_fatal`, so it **aborts the process** rather than returning an error the shell could handle. The reported "only after logging in" is a timing tell, not a state one: a heavier screen widens the window between sampling the size and configuring the surface, so the drag outruns the reconfigure. **Fix:** make the outcome a type — a transient skip requests another redraw and keeps the same display list (so the retry costs no rebuild), and only `Unavailable` falls back. That also removes a silent second bug: one bad frame used to degrade the whole session to CPU readback with a message blaming the surface size. **Secondary hardening:** `Presenter::new` sampled `window.inner_size()` *before* blocking on adapter+device requests and configured with that stale size — now re-queried immediately before `configure`, and clamped to `max_texture_dimension_2d` (configuring past it is fatal too). Both presenters (`wgpu` and `softbuffer`) return `Option` instead of `expect`-panicking, because this constructor now runs mid-session on a fallback path where a panic kills a running app. **Verified live, both directions:** the pre-fix build died after 129 resizes; the fixed build survived 1600 across three rounds with the direct path still attached. What is NOT closed: `Surface::configure` racing a resize remains fatal-by-construction in wgpu 22 at `attach_surface`/`resize_surface`/`Presenter::new` — nothing outside wgpu can catch it. This removes the race we were *creating*; the residual one belongs to the dependency.
