# R6.3 — the swapchain risk does not apply, and MSAA decides the design

*2026-08-08. Specified, then implemented against the corpus it specified.*

**Status: landed on both paths.** `render_at_scale_dirty` (readback) and
`present_to_surface` (swapchain) both cull the display list to the damage region
(R6.2) and scissor the redraw into the retained root (R6.3). `app.rs` passes
`last_damage` down; before this it computed the region and discarded it with the
comment *"granularity is ignored — the GPU renders the whole frame anyway"*.

R6.3 (scissored partial redraw with `LoadOp::Load`) carried an **open
correctness question** that the plan's risk register listed unresolved:

> `get_current_texture()` on a double/triple-buffered swapchain does **not**
> guarantee the acquired image holds *last* frame's content. Partial redraw
> needs either a guarantee or an explicit per-image damage history.

## That risk is not Lumen's

Lumen never renders into the swapchain image. `present_to_surface` encodes the
frame into an **offscreen root texture**, then runs a separate blit pass that
does `LoadOp::Clear` and draws a fullscreen triangle sampling that root
(`gpu.rs`, `blit-pass`). The swapchain image is therefore fully overwritten on
every present, and its prior content is never read.

So R6.3 would `Load` from the *root target* — which Lumen owns, and which
**persists since R6.4**. The swapchain guarantee is irrelevant to this
architecture. The risk-register entry can be closed: it was inherited from
designs that render directly to the swapchain.

This also means the blit stays full-frame. That is not a missed optimisation
worth chasing: it is one fullscreen triangle, against the vertex, fragment and
upload work for every command in the frame, which is what the scissor removes.

## MSAA is the part that actually constrains the design

`sample_count` is 4 wherever the adapter allows it, and each layer pass renders
into a multisample attachment that **resolves** into the single-sample target.
That breaks the naive plan:

* Loading the single-sample `resolved` and scissoring does not work — the pass
  renders into the MSAA attachment, which holds nothing.
* Dropping MSAA for damaged frames does not work either — tessellated paths
  would lose edge AA inside the damage rect and not outside it, so a scroll
  would visibly change the quality of what it passes over.

**Both attachments must be retained and both loaded.** The MSAA attachment keeps
last frame's samples everywhere; the scissor confines new drawing to the damage
rect; the resolve then covers the whole attachment and reproduces last frame
outside the rect and new content inside. Resolving the full target every frame
costs bandwidth but no draw-call encoding, which is the cost R6.3 exists to
remove.

The pool from R6.4 must therefore hand the *root* a dedicated retained slot
rather than a generic `acquire`, because "first free target of this size" is not
necessarily the one holding last frame's pixels when a frame has nested layers.

## Invalidation — what must force a full frame

1. **Atlas clear.** On overflow the glyph atlas is cleared and every glyph
   re-packed, so a retained target's text pixels reference slots that have moved.
   R6.5 made this 4× rarer; it did not make it impossible, and "rarer" is not a
   correctness argument. The existing `atlas_overflow` flag is the hook.
2. **Size change**, which R6.4's key already distinguishes.
3. **Any frame where damage is `Full`**, including the first frame after attach.
4. **A backdrop layer in the frame** — it samples the parent's resolved content,
   so a partially-updated parent feeds it stale pixels.

## What the corpus caught that inspection did not

Two things, both of which would have shipped:

**`Load` skips the clear.** Anti-aliased and alpha-blended edges then composite
over *last frame's* pixels instead of over the background, so a moving shape
leaves a ghost of itself. A clear op cannot fix it — clears apply to the whole
attachment, not the scissor — so the damaged region is repainted with an opaque
background quad as the first draw inside the scissor. The two cases that failed
were an anti-aliased edge and the frame boundary; both look perfectly correct in
any single-frame test.

**Culling before deciding.** Culling to the damage region and only then
discovering the frame could not reuse the retained target produces a
full-cleared frame drawn from a partial list — everything outside the rect
simply missing. `reusable_scissor` is now the single decision point and runs
before the cull. The corpus's resize case caught it; the backdrop check inside
it deliberately reads the *uncalled* list, since culling could drop the backdrop
command and make an ineligible frame look eligible.

**Retention fought the pool.** Routing the root through `TargetPool` meant the
retained root held a reference, the pool judged it in-use, allocated a
replacement, and the count climbed every frame to the per-key cap. The root now
owns a dedicated target per size — cleared on a full redraw, loaded on a damaged
one — which is simpler and makes retention obviously correct. It also emptied
the pool for flat scenes, which broke R6.4's own test into asserting nothing
until it was rewritten around a nested layer.

## Why this was specified before it was implemented

The failure mode is wrong pixels **only in particular damage patterns**. Every
GPU test in this repo renders one frame and checks pixels, and would pass against
a partial-redraw path that is subtly wrong. Twice in this session a test passed
while proving nothing — the multi-page atlas probe that never left page 0, and a
timing harness that measured a pump that never rebuilt — so this is not a
hypothetical standard.

What R6.3 needs before it is safe to land is an **equivalence corpus**:
partial-redraw output byte-compared against full-redraw output across a set of
damage rectangles (edge-straddling, sub-pixel, zero-area, full, and one that
lands entirely on a nested layer), on both drivers. `damage_equivalence.rs`
already does exactly this for the CPU/readback path and is the model to copy.

Landing the mechanism first and the corpus afterwards would put a silent
rendering defect in the tree for the length of that gap — which is the same
trade that let the GL gradient bug survive for months.
